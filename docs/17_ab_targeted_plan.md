# A/B 定向验证计划

后续载体和执行清单现由 [docs/21](21_appworld_ab_execution_plan.md) 落实更新；
本文件的 A/B 定义与语义分析原则保留，旧 ALFWorld 选样安排不再重复执行。

2026-09-12。依据最新研究讨论修订。当前交付是计划，不启动新的模型请求。
本计划取代后续工作中默认广泛采样、优先单规则 mask 的安排；保留既有结果、
官方机制、模型配置、反馈隔离和费用记录要求。研究目标是检验猜想，不要求得到阳性。

## 1. 研究问题与现有证据

**A：从轨迹中可靠提取多条记忆，并持续维护整个记忆集合。**
包括事实与来源、适用条件、概括强度、信息取舍、记忆间的互补/冗余/冲突，
以及新增、合并、修订、删除、保留的合理性。A 可独立取得证据，不必先证明下游失败或 H2–H4。

**B：记忆如何影响行动、证据获取、探索，以及更优策略的发现、比较和采用。**
既包括错误/不完整记忆限制纠错，也包括正确且有用的记忆使 agent 停留在次优路径。
不能只看任务成功，也不能把少探索、轨迹不同或某个局部动作改变直接当作问题。

**A+B：经历形成记忆，记忆影响新经历，新经历再用于更新记忆。**
只有取得相应链条证据才讨论闭环强化或长期恢复；不把 updater 的保留门槛本身当作证明。

已有结论沿用 docs/15–16：

- A 有具体案例：灯任务成功时序错记；Book M1 把自行加入的 desk_1 错归因为初始观察，写入两条规则。
- 反向证据同样重要：清洗任务合理补充开门条件；Book I1 提出明确标注待验证的效率建议。
- 两批筛选尚未支持所测试渠道导致纠错/改进受限；不继续旧 rule_3 或 Book 呈现候选。
- “模型较强使样本难找”是待检验解释，不能替代对任务条件、知识冗余和干预范围的检查。

本轮计划核对了研究定义与已有报告，未重新审计全部原始 artifacts。
下一交付中的案例判断仍须回到原始请求、动作、观察和实际更新。

## 2. 工作节奏：两次集中交付

|交付|工作|完成标准|
|---|---|---|
|一：语义选样与执行准备|复用旧数据完成 A 案例；定向查找 B 迁移边界；必要的无模型环境验证；准备唯一批次|明确任务/checkpoint、语义预测、干预、指标、预算及可执行入口，或有证据地说明当前环境不适合|
|二：有界执行与综合判断|在具体批次获授权后一次执行，完成官方更新并逐样本分析|分别回答 A、B、A+B，给出支持、反证、解释边界与继续/停止决定|

不拆成每个小修复、测试或分析一次审批。第一交付把必要接线和检查做完，
使后续只需审阅一个完整批次。新的付费授权范围在该批次中写明，旧批次预算不自动沿用。
进一步重复确认或纵向实验仅在有可解释信号时考虑，不默认增加第三批。

## 3. A：提取与更新两部分一起设计

### 3.1 提取：轨迹到记忆集合

优先复用两组已有资料，不重新生成相同错误：

1. 校准 task_00 的失败、重规划、最终成功及规则/技能形成，用于区分成功条件、
   实际时序、未执行代码和多记忆共同来源。
2. Book 分支 M1 的初始观察、非法 desk_1 动作、Builder 输入与 rule_0/6 写入；
   I1 作为合理提出待验证优化的对照案例。两者轨迹不同，不能视为控制变量的 updater 比较。

每个案例先整理一份简短“证据—主张”表，再检查完整记忆集合：

|层次|检查问题|
|---|---|
|直接事实|观察、动作结果、时序、来源和实际执行是否对应？|
|条件与概括|是否把充分条件写成必要条件，把局部经验写成普遍规律？|
|信息取舍|是否遗漏会改变后续决策的条件？省略其他细节可以是合理压缩。|
|集合关系|多条规则/技能是否互补，是否存在条件冲突、同源证据重复，或规则与执行范例不协调？|
|知识身份|已验证经验、未验证但合理的建议、通用先验是否被混为一谈？|

不规定应提取几条记忆，不追求唯一标准文本；记录若干合理抽象均可。
“未被当前轨迹验证”不等于“错误”；已有知识可以支持通用判断，但不能伪造当前轨迹验证。
明确事实矛盾、缺乏支持的概括、待验证建议和合理更新分别报告。
对遗漏，说明缺失信息如何改变决策，不能只因没写入而判错。

### 3.2 更新：新证据到集合修订

先复用增量 task_01 → task_04/08 的真实连续更新链，阅读中间状态和 intervening tasks，
检查开门条件如何进入规则、技能及后续验证；不能把不相邻快照差异都归于某一个任务。
此链可提供合理更新的证据，不为得到故障而排除它。

从现有 checkpoint 选择一个还缺关键证据的案例，最多补两条后续任务：

- 一条同条件复用：旧经验成立时，检查合理保留与无依据扩大概括。
- 一条条件变化/纠错/改善任务：实际获得新证据后，检查限定条件、修订范围及相关记忆是否协调。

优先采用同一 memory 实例连续运行，保留整个集合。需要隔离两种新证据的影响时，
才从同一个 checkpoint 独立分支，明确这与连续更新回答不同问题；不默认两种都跑。
自然序列的观察不是对某项输入因素的因果证明。

判断 updater 前必须确认其实际输入包含什么。若 actor 没取得关键证据，不能据此判定
updater 忽视了该证据。必要时可给官方 updater 输入真实环境执行获得的诊断轨迹，
但须单独标为诊断输入，保留原生接口，不冒充自主探索或自然闭环证据。
不虚构反馈，不把人工给出的修订答案写进记忆。

## 4. B：以迁移边界选样，不以现有 mask 工具选样

### 4.1 每个候选是一组来源与目标任务

寻找以下关系：

1. 来源任务：一种策略在这里合理，官方 updater 自然形成相关 K。
2. 同条件任务：相似情境中该策略仍有用，提供合理复用的参照，优先复用已有轨迹。
3. 变条件目标任务：表面类似，但某个决策相关条件变化，使另一策略更适当。

变化应能通过合法公开交互发现。例如搜索/操作条件、目标数量、可利用的中间状态，
或取得多个目标的机会发生变化。加热/双物体等类型只是检索方向，不因类型更难就自动合格。
只换物体名称不足以成立；旧策略和替代策略在当前条件下的差别必须具体说明。

第一交付最多详细审查 10 个新增任务配置、保留最多 2 个候选、推荐 1 个执行。
任务配置或 evaluator 信息只用于研究侧选样/评估，不进入 actor/updater 上下文。
需要执行时，优先对最终候选做短小的无模型环境诊断，不重跑整套 reset/校准。
研究者找到更短路径只证明可行机会，不证明 agent 当时知道它，或它是全局最优。
应明确从 agent 已有公开信息出发，什么合理动作能够发现/比较该机会。

若受检任务没有足够的条件差异，明确结束该次搜索；可以提出一个标记清楚的环境诊断变体，
或提出下一环境的研究理由，但本交付不自动修改 benchmark、接入新 baseline 或扩大扫描。

### 4.2 允许按问题选择干预的范围和时间

可选：相关记忆集合移除、任务开始时去掉 K、关键决策处去掉 K、暂时移除后恢复。
用户已允许这些设计，不再默认只屏蔽一条规则，也不要求为“更干净”而留下几乎等价的全部替代渠道。
第一批只实现并执行其中一个最合适的设计，不建设通用干预框架。

- 来源任务形成 K 后，在**同一个目标任务**比较完整 K 与登记干预；跨轨迹形成/使用记忆不变。
- 任务中分支须共享相同的既有经历、环境状态和公开观察，从实际可行的决策边界开始。
- 只停止后续注入不等于消除先前影响：上下文、旧计划、已加载技能/helper 可能仍携带 K。
- 若重建上下文或清除已加载代码，明确删掉什么、保留什么；两组采用一致的重建程序，
  保留相同任务内事实，不能把重启损失或额外提示误当成 memory 效应。
- AutoManual 一次生成可含多步动作。环境动作步不等于模型决策步；任意暂停代码不会自动触发重规划。
  优先使用原生 LLM 调用边界；若需新增调用/中断执行，两组对称设置并标注诊断性机制改变。
- “去掉 K”需列明规则、技能、历史等学习记忆渠道；保留的静态提示、基础工具和通用先验也要说明。
  广范围移除的结论是这个记忆集合/使用策略的作用，不能归因于其中单条规则。

具体方案应提前固定时点/触发条件、移除范围、持续区间和是否恢复。
首次 screening 固定 I1 → M1 → M2 → I2 → I3 → M3，3 次/组，不并行，不补跑追阳性。
若采用更广范围干预，解释工具能力变化、提示长度、知识冗余等实际影响；不为了排尽所有混杂增加对照矩阵。

### 4.3 B 的结果判据

在执行前具体写出：旧策略、新条件、关键证据事件、可行替代策略及任务成本。
逐轨迹判断是否发现、尝试、比较、采用该策略，不只计算一个代理指标。

- 纠错：干预是否帮助获得相关反证，并做出正确调整？
- 改进：干预是否帮助发现或采用有实际收益的策略？收益需考虑成功约束及发现/试错成本。
- 仅成功率、动作变多、早拿一次、随机走不同路线，都不足以支持 B。
- 3 次/组仅作有界筛选；全阴性不证明普遍无效，个别阳性也不证明稳定效应。
- 观察更新是本批的一部分，但只有 memory → 行为/证据 → 更新的链条有支持时才讨论 A+B；
  更长期自强化/恢复仍需后续证据，不自动追加 H4。

## 5. 下一付费批次的规模与预算准备

暂定最多 11 个新任务执行名额：来源记忆形成最多 3、A 的补充更新最多 2、B 分支 6。
这些是候选成熟后的规划上限，不是必须跑满；已有 checkpoint 和 A/B 共用轨迹均可减少执行数。
若 3 个来源任务没有自然形成所需记忆，停止 B 部分并报告，不伪造记忆或继续追加来源任务。
A 缺乏明确补证需要时不占用两个名额，B 没有合格候选时不强行启动六分支。

第一交付须固定实际执行清单、来源选择规则和条件式停止规则，依据相似任务实测用量
计算费用预期及 task/run 的请求/token/USD/CNY 上限。模型请求和 embedding 均计入，
币种分开；费用预留继续使用已有保守机制。此文不新增金额授权，不用旧文档历史价格充当新报价。
若真实来源形成的 K 与预设候选不符，不能临时改目标、扩大干预或挪用额度另跑候选。

## 6. 给 coding-agent 的执行要求与交付物

现在执行第一交付：

1. 阅读本计划、docs/00–01 和 docs/15–16；结合原始 artifacts 完成上述 A 证据表及更新链分析。
2. 有界查找迁移边界，最多详细审查 10 个新增配置；把纳入/排除理由保留在同一报告，避免只展示好故事。
3. 推荐一个候选，完成必要无模型诊断、最小接线、实际请求中的干预 diff 验证及固定批次计划。
4. 输出一份集中报告：A 已知结论/未知项、B 条件差异与可发现性、候选证据、运行清单、预算、
   预定判据与停止条件。没有合格候选也应交付明确分析，不用更多工程开发填充进展。

分析必须真实阅读 actor/updater 可见消息、执行过的动作/观察和 memory 变化，
引用 task/call/update ID 与短原文。自动提取只负责定位，测试通过不是 A/B 成立的证据。
争议主张标注不确定性，不强制为每条记忆赋分，不创建大型标注系统或 LLM judge 流水线。

复用现有两个 conda 环境。所有运行/测试/联网通过 scripts/direct.py，客户端继续禁用代理。
不改动密钥或输出凭证。只为实际改变且影响结论的行为做必要回归；纯分析/文档不跑全套测试，
不重复 API probe、依赖安装、上游 patch 重放或既有校准。保留旧 artifacts，不创建 Git commit。

第二交付在批次获授权后执行到底：按固定清单运行、正常完成原生更新、合并必要小修复与语义分析，
报告所有成功、失败、阴性和正常纠错。无需为例行检查或小型可逆修正反复请求确认。
