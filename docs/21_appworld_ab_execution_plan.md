## 3. 具体任务组

### A：资金条件变化下的多记忆提取与集合更新

原生任务序列：`60d0b5b_1` → `37a8675_1` → `60d0b5b_2`。

- `60d0b5b_1`、`60d0b5b_2`：train，退还误收款。官方 setup 将 Venmo 余额设为该笔退款金额，
  直接用余额退款合理；还涉及身份匹配、请求状态/时间和金额来源等互补知识。
- `37a8675_1`：dev，向指定电话号码对应的人付款。官方 setup 将 Venmo 余额置零，
  并将除一张未过期卡之外的其余未过期卡余额置零。资金来源处理必须不同。
- `37a8675_1/2/3` 都是余额为零的条件，不能把它们当成余额充足/不足的对照。

这一序列用于观察：从一条经历提取多条记忆时，身份、金额、资金来源和验证条件是否被妥善区分；
遇到资金失败/替代支付证据后，是否补充适用条件；回到余额充足任务时，能否合理保留原知识。
并不要求它造成 B。一次支付错误后正常读文档、换资金来源并修复记忆，是重要反向证据。
不能假设每个账户都有公开可读的银行卡余额；可用证据包括公开文档、卡列表和实际支付错误响应。

### B：优惠比较中“保留旧方案”的适用条件反转

采用同一个原生场景 `432dc7a`，全部属于 test-challenge：

|角色|任务 ID|研究侧核对的差异|
|---|---|---|
|来源 S1|`432dc7a_2`|旧优惠满足门槛，新优惠不满足当前购物车金额门槛；保留旧优惠合理。|
|来源 S2|`432dc7a_3`|两种优惠均满足门槛，但旧优惠折扣更大；保留旧优惠合理。|
|目标 T|`432dc7a_1`|两种优惠均满足门槛，新优惠折扣更大；应选择新优惠。|

任务本来就要求比较已应用优惠和新收到的促销邮件，并选择更便宜的方案。
S2 与 T 的任务指令相同，包括送至家中；适当选择的差异来自任务状态，不是人为新增目标。
S1 另有送至工作地点的要求，应保留并记录，不能抹平这个差异。
具体金额及判定计算留在本地 `research_evidence.json`，不需要将答案写入 actor 提示。

合法证据路径：通过 Gmail 查看相关邮件获得候选码，通过 Amazon 的
`show_cart`、`apply_promo_code_to_cart` 等公开接口比较。
`show_cart` 的文档包含 `promo_valid`、`discount`、`total_cost` 和当前 `promo_code`。
比较期间可能改变当前应用的优惠，需要记录旧状态，最后选择正确方案。
必须在官方 API 中核对试用、失败、恢复旧码的实际语义，不能将静态数据库数值直接当作 actor 已知信息。

这里预期的记忆影响是：来源连续保留旧优惠后，自然形成的相关承诺是否使目标任务
跳过/不充分检查新优惠、过早结束比较，或即使获得比较信息也仍偏向旧方案。
**来源任务应当先合理比较再保留旧优惠；不能把跳过任务明确要求的比较说成来源中的最优策略。**
若 ACE 自然形成“每次检查两种方案、按条件选择”的记忆，则它可能帮助迁移，应如实报告。
目前没有形成任何 ACE 学习记忆，不预写“旧码总是更好”的 K。

这些 test-challenge 任务明确用于 exploratory 机制研究，已经过研究侧检查；
不再充当未见测试，不用这一小组推断整体 benchmark 成绩。
不再优先采用 `c9458ed` 的多人优惠码场景；已定位但不扩展到新一轮搜索。

## 4. ACE 源码边界与最小接入

固定 [ace-agent/ace-appworld](https://github.com/ace-agent/ace-appworld)
commit `928e86877d34cd10eaba159606386f93a1765090`。
安装该 fork 的环境与实验包，不以当前独立 AppWorld HEAD 替代它。
独立 conda 环境建议命名 `memory-ace-appworld`，Python 3.11；不修改现有两个环境或 base。

源码复查的关键事实：

1. `ACE_online_no_GT.jsonnet` 默认指向在线无 GT 路径、原始八条 initial playbook；
   保留原生 Generator–Reflector–Curator、静态示例和更新逻辑，只做项目已允许的模型替换与观测接线。
2. `adaptation_react.py` 的当前 curator 校验只接受 ADD。
   A 可以评估新增条目的事实/条件、集合协调和追加式修订，但不能把未物理删除旧条目直接认定为模型失误，
   也不能声称这个 fork 完整代表论文中的全部更新能力。
3. `task_completed()` 查询的是 `supervisor.show_active_task` 的完成状态；它并不等于 evaluator 判定成功。
   `solve_task_wo_gt` 在完成后仍计算评价报告，所查 no-GT 模板没有将该报告/参考解答插入消息。
   `required_apis` 虽被放入模板参数，当前 generator 模板未使用它。接入时核对最终请求与控制流，
   不仅检查变量名或配置名。无需把 AutoManual 的 won 例外扩大到 AppWorld。
4. 达到 max_steps 时该路径未统一调用 curator；不要擅自补调用。
   最后一段 `world.execute` 的输出通常到下一轮 generator 才加入消息，若直接结束，
   updater 实际收到的 history 可能没有终段输出。记录真实边界，不把环境中发生过等同于 updater 看见过，
   不为了得到更完整证据而默默修改原生输入。
5. 关闭所有角色的响应结果缓存与自动网络重试；保留 provider token cache 的正常计费。
   原 cost tracker 不足以覆盖全部角色硬预算，复用本项目共享 ledger。
6. 默认模型替换为项目 DeepSeek、non-thinking、temperature 0；记录请求与返回身份及当前别名说明。
   不需要引入 embedding 或其他付费模型服务。不要使用上游示例凭证。

隔离保持研究必要的范围：实验 actor/updater 仅有原生公开任务/API 信息，
不能直接读数据库、参考解答、evaluator 或本报告。真实 transport 凭证不交给生成代码。
用上游现成执行限制/进程边界和现有设施完成针对性检查；不建设新沙箱平台或通用 RPC 框架。
若这需要重大机制改写，交付具体阻塞及最小选择，不以长期安全工程代替科研推进。

## 6. 后续一次授权的有界执行方案（待上述交付落实预算）

拟在一次批次授权中包含五任务接入/校准与条件式六分支，最多 11 次任务执行。
这不是本轮付费授权；先交付具体入口和金额，再统一审阅。

固定校准序列：

1. `60d0b5b_1`：同时承担首次真实接入与 A 多记忆提取；
2. `37a8675_1`：A 的新条件与更新；
3. `60d0b5b_2`：A 的旧条件再次复用；
4. `432dc7a_2`：B 来源 S1；
5. `432dc7a_3`：B 来源 S2。

每次新建原生任务世界；同一官方 agent 的 playbook 顺序继承，禁止继承上个世界的运行变量/状态。
采用 fork 配置的 `random_seed=123`，相同目标分支固定一致。任务数据库本身按官方 ID 固定，
不要把改运行 seed 误当作生成另一个任务实例。
五任务用量、原始轨迹、记忆演化和离线 reset/干预证据合并满足接入条件；不另跑五个纯校准任务。
第一任务满足既有 Phase 0 项目时记为通过；不强迫任务成功来掩盖 evaluator/接口问题。

第五任务后立即做一次语义判断，保存原始来源轨迹及全部更新：

- 来源阶段未正常完成、身份/费用不确定、设施故障、预算不足，停止后续付费调用，不补跑。
- 没有自然形成与保留旧方案、比较/验证或提前停止有关的可检验承诺，停止 B 六分支，保留 A 分析。
- 若只有清楚适用条件的全面比较知识、没有明确的潜在探索限制，优先报告健康迁移假设，不凑分支。
- 不能为满足条件修改 K、挑另一个目标、改干预或追加来源。是否存在相关承诺须给条目原文与来源证据，
  不能用词频、规则数或一个自动标签替代。

满足登记条件和剩余额度时，执行 `432dc7a_1` 的 I1 → M1 → M2 → I2 → I3 → M3。
两组均从第五任务后的完整 K 独立恢复，每次使用独立目标世界。

**唯一干预：目标任务开始时，Generator 只呈现官方 initial playbook，移除本批来源形成的全部新增 playbook 条目。**
Intact 呈现完整 K。原生 initial playbook、静态 demonstrations、工具与目标指令两组相同。
仅改变 Generator 的 playbook 呈现；Reflector/Curator 都保留各分支完整的原始 K，接收各自实际经历并原生更新。
每分支更新后保存，不把它传给下一分支。实现时核对最终请求，不能临时清空共享 playbook 后漏恢复。
这个对照识别的是学习记忆集合在行动阶段的作用，不是单条优惠知识的净效应；其他学习知识与长度也随之变化。
initial playbook 和静态示例仍在，名称使用 `learned-playbook-removed`，不称“完全无记忆”。
本轮不实现任意步骤清除、第二个干预或更复杂的知识去重。

保留原生最多 40 个 generator 决策轮；所查无 GT 完成路径另有一次 reflector 和一次 curator。
因此可先以每任务最多 42、整批最多 462 次模型 transport 作为结构上限估算，
coding-agent 须核对实际调用路径并设置更有约束力的 token/金额上限，覆盖所有角色，零自动重试。
这不是预期用量，也不要求跑满；若所选接口有额外模型调用，不可默默超出清单。
完成五任务后的预算校准只能在已批上限内缩减/停止，不自动扩大金额。

## 7. 分析与停止标准

逐样本阅读实际 Generator/Reflector/Curator 请求、执行代码、API 输出和完整 playbook diff。
重点区分：API 在程序中返回过、结果被输出到模型上下文、actor 做过正确比较、updater 实际看见过。
程序内比较即使没有逐项打印也可能成立；可用已执行代码、API 记录与可见输出共同判断。

- A：条目事实/来源、条件、充分/必要性、多条互补/冲突、合理省略和增量修订；保留正常更新与不确定主张。
- B 证据获取：是否发现新邮件/候选、取得有效性与价格比较证据、是否过早终止搜索或比较。
- B 策略采用：即使信息都取得，是否仍选择更差方案；这种情况可以支持策略选择层面的 B，
  但不能同时声称证据没有取得。需有同目标干预差异，不能只看来源成功与目标失败。
- B 改进：最终方案收益与探索成本分别报告，使用官方任务要求、实际成交状态及调用成本；
  不把多一次调用自动算坏，不用更高成功率替代过程解释。
- A+B：只在行动/证据受记忆影响、且其后更新与该经历相联系时讨论链条；
  E* 出现本身不要求 updater 最终正确更新，完整闭环结论需要更多证据。

六分支后统一交付所有正反结果，不追加重复或换题。若完整学习记忆移除仍未产生有意义差异，
暂停这个候选，讨论任务可诊断性、模型先验与 baseline 的具体机制，不宣告 B 普遍不存在，
也不继续扩大 mask 寻找阳性。

所有命令、测试和联网继续经 `python scripts/direct.py`，客户端显式禁用代理并保持 TLS 校验。
不修改 `.env`、全局环境或旧 artifacts，不安装本地推理模型，不创建 Git commit。
